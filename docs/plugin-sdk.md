# Aura declarative plugin SDK 1
A plugin is a JSON manifest, not an executable binary or script. Save as .auraplugin. Required fields: app "aura-plugin", sdk 1, lowercase id, semantic numeric version, name, effects (1–4 existing native effect descriptors), macros (0–6). Each macro has lowercase id, label, default 0–1 and mappings: effect (zero-based index), parameter ("value" or native secondary parameter), from/to (inclusive bounded native values, may be descending). A parameter can be mapped by only one macro; max 32 mappings. No arbitrary code, URLs, external graph wiring or nested plugins. Example: {"app":"aura-plugin","sdk":1,"id":"quiet-trim","version":"1.0.0","name":"Quiet trim","effects":[{"type":"trim","value":0}],"macros":[{"id":"amount","label":"Amount","default":0.5,"mappings":[{"effect":0,"parameter":"value","from":0,"to":-12}]}]}.
Import in Tools > Plugins, then explicitly add to selected track. Three factory manifests, 32 local definitions, four instances per track, eight total native processors including normal inserts and bypassed processors. Plugins execute after regular inserts in the same realtime/offline channel graph. Per-instance manifest, macro state and bypass are embedded in existing project JSON/portable packages; no external dependency on the local library. Invalid/over-budget imported states preserve native processing and show warnings in the Plugins workspace; no code execution. Dry export clears plugins. Undo applies to instance changes. No WAM/VST/AU, executable third-party isolation, parameter automation, plugin-specific latency reporting, or custom DSP ABI. These need separate host work.
