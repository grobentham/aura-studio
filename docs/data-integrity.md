# Import and recording integrity
Legacy JSON imports require all referenced audio to be embedded; metadata-only MIDI projects remain supported. All embedded audio gets fresh UUIDs, consistently remapping regions, original takes and sampler zones. Existing provider-based package restore already remaps IDs; add-only writes are now performed in one atomic asset transaction. Source bytes are preserved, including original WAV bit depth; JSON export prefers persisted source bytes over re-encoding. Decode checks precede project switching, and imports reject missing/malformed sources, collisions, 192 MiB encoded non-streamed / 256 MiB cumulative decoded audio budget. The decoded cap is checked after each decode, not a guarantee against pathological compressed files. Project identity changes only at commit; snapshot guards reject edits during preparation. Cross-database project save is not atomic with asset storage; orphaned fresh assets may remain if final save or commit fails. 
Recording: same-session completion timers, detach message/error handlers when finalising, clear timers on failure, extend final flush watchdog to five seconds. Recurring archive test failed after the worklet was started; existing evidence does not establish the root cause. The test now waits for committed frames with a bounded timeout and prints status/frames/errors on failure. Same archive/audio/no extra track assertions retained; actual hardware endurance and root-cause confirmation still outstanding.

Phase 1 follow-up: failing collision fixture had no required take name; corrected fixture without weakening assertions. Imported project metadata is committed before activating the new identity. Storage conflicts check latest record and monotonic timestamps, including trashed records. Failed saves retain a per-tab local draft when localStorage quota permits, exposed in Recovery history as recoverable copies. Existing source data is checked before project switching/revision recovery; asset health inventory includes saved/trashed projects, revisions, drafts, undo/redo. Unreferenced assets are reported only; destructive cleanup requires coordinated ownership across tabs. Master preview snapshot no longer overwrites its before-level metrics. Actual recording root cause remains unproven. Recovery draft quota and failed final commit can still require portable backup; audio assets stored before metadata can remain unreferenced after interruption. Full engine and undo/redo audit not yet complete.

Further safeguards: undo/redo blocked during protected operations; legacy JSON export uses the captured project asset list/title rather than a changing live selection. Asset presence is checked even for unchanged saves. Startup reports missing source audio rather than claiming success. Recovery copies do not overwrite another pending draft. New fixture injects a failed metadata commit and checks the active project is unchanged. Remaining: complete engine-by-engine edit/lifecycle audit, browser and hardware reliability, cross-tab cleanup coordination and corruption/hash verification beyond existing length/format checks.

Checksum follow-up: new portable project and sound packs include optional v1 integrity metadata, SHA-256 of concatenated SHA-256 digests of 1 MiB audio chunks. Verification detects accidental same-size audio corruption before import. Old packs remain readable and are labeled unverified; this is not an authenticated signature or metadata checksum. Memory for digesting is bounded to one chunk plus digest list. Web Crypto secure context required. Integrity fixture's nine assertions passed, but the suite reported a page error from a null transaction rejection; error handling now uses transaction abort for save conflicts, normalizes null rejections and logs error stacks. Full rerun required.

Scoped rollback: all JSON and binary imports generate fresh UUIDs in the shared importer. Once an add-only asset transaction commits, its new IDs are tracked until metadata activation. If preparation fails, the importer deletes only that private staged set, and only after confirming its destination project record does not exist. If metadata committed but the activation guard fails, the saved copy and its assets remain. If storage is unavailable or the tab crashes, staged audio can remain; arbitrary orphan deletion remains disabled. Explicit unsupported version rejection retains unversioned legacy, v1 and v2 compatibility. Fault injection now checks staged asset rollback and version rejection.

Lifecycle audit slice: seven direct-output preview workspaces (Master, Mix Next, Vocal, Instruments, Stems, Sound Library, Coordinator) share a cleanup registry. Starting a competing preview, playback, recording, stopping transport, switching/importing projects or pagehide stops registered previews. Epoch/project/panel guards prevent delayed resume/render results from starting stale audio; synth preview disconnects on completion and loop preview disconnects immediately. Recording setup checks project/input identity across asynchronous preparation; frame gaps and queue overflow stop accepting blocks before exceeding the queue cap, and independent node cleanup avoids skipping later disconnects. Older routing/stream fixtures now assert the shared importer allocates fresh independent IDs and preserves both original and imported bytes, instead of expecting caller-assigned identities. Full CI required; not a complete audit of all audio pathways or proof of physical recording stability.
